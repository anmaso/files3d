files3d · concept sheet 02 · revision C

Floors as columns

Each opened folder now steps out to the right of its parent, like a Miller column built in 3D. The parent floor stays in full view, and you can branch from any folder on any visible floor. Every file and folder is named on its floor, and the floors sort by name, size or date. Below are three ways to lay out a single floor.

Revision C views the floors through a perspective camera, set lower in turn and higher in tilt than isometric, so rows run almost level and every line of text rises gently to the right, the way a page tilted toward you reads. Labels are painted on the floors and follow the same perspective: each letter is placed where it lies on the floor, so names on far floors are smaller and foreshortened, like markings on a real floor. Option D

Terraces

Each floor is a narrow list with one row per item. Sorting paints group markers on the floor: letters for name, size bands for size, or This week / This month / Older for date. The open folder's row runs into a lit ramp that climbs to its floor on the right. Click a folder on an earlier floor to branch from there. Opening a second folder from the same floor adds it to the same level, behind or in front of the first with a clear gap, and a dashed line ties each one to its row. Floors never swap places: clicking one that is already open just makes it current. Every floor except the root has an × to close it. It stays readable, its row on the parent keeps a dashed outline, and clicking it brings it back to the front. In this example, lib/ and components/ were opened before pages/.

Option E

Tile hall

Square floors with a grid of equal tiles, read from back-left to front-right. A floor holds about three times as many items as a terrace, but long names get cut short. Suits folders full of similar files, like images. Clicking a file opens a preview floor on the right.

Option F

Measured floor

The sort key becomes a ruler down the left edge of each floor. Items stand at their actual value, so gaps and clusters show up: a run of edits last week, or one large file among small ones. Name uses letter marks, size a log scale, date a time scale. A dashed tick shows where an item was nudged aside to avoid a neighbour.

Next decisions

Open questions

  • Deep paths

    After four floors, the oldest ones fade out on the left. They could instead fold into a stack of thin slabs, one per level, that you can still click.

  • Long folders

    A terrace with 300 rows runs off the back of the screen. Either the camera glides along the floor, or rows past a limit fold into a "more" block.

  • One sort or many

    These sketches sort every floor the same way, as Finder's columns do. Per-floor sorting is possible but harder to read across floors.

  • How many earlier floors

    The sketch keeps up to three open floors per level, in fixed places behind and in front of the first. More than that crowds the view; a count chip ("+3 earlier") could stand in for the rest.

  • Default angle

    Perspective with floor labels feels most like a real place. Front, high keeps every label the same size. Three-quarter shows block heights best. Text on far floors could be set slightly larger to stay legible.

  • Ramp or bridge

    The connector climbs half a floor per level. A flat bridge with floors at the same height would read more like 2D Miller columns, with less sense of depth.
